# Express 接口学习阶段：从一个函数逐步演进到分层架构

## 0. 先纠正学习顺序

这套生产级项目架构对大型 Express 项目有价值，但它不适合作为初学者的第一站。

如果一开始就同时看到：

```text
schema
dto
entity
controller
service
repository interface
mysql repository
mapper
route
module
```

注意力很容易全部耗在这些问题上：

- 这个类型从哪个文件导入？
- 为什么这里又跳到另一个文件？
- Entity、DTO、Row 有什么区别？
- 为什么一个创建用户接口需要打开十个标签页？

结果是真正的业务流程反而看不见了。

正确的学习方式应该反过来：先把业务流程放在眼前，确认自己能完整理解，再根据代码出现的真实问题逐步拆分。

这篇教程只学习一个接口：

```http
POST /users
```

始终只有四个业务动作：

```text
校验输入
  ↓
检查邮箱是否重复
  ↓
创建用户
  ↓
返回结果
```

我们分五个阶段学习：

```text
阶段一：所有逻辑都在 app.post 中
阶段二：抽出 createUser Service 函数
阶段三：抽出 Repository 对象
阶段四：把 Service 改成 class，并注入 Repository
阶段五：最后加入 TypeScript DTO 和 Repository 接口
```

阶段一到阶段四始终修改同一个 `src/app.js`。不要每学一个概念就立刻增加目录和文件。

## 1. 公共准备：MySQL、依赖和环境变量

虽然我们简化架构，但不会用一个无法迁移到真实项目的假例子。从第一阶段开始就使用 MySQL、mysql2、手写 SQL 和数据库唯一索引。

### 1.1 安装依赖

这篇教程固定使用同一套版本，避免你今天和一个月后安装出不同结果：

```text

express   5.2.1
mysql2    3.23.2
dotenv    17.4.2
```

这里选择 Node 20.15.0，是为了与现有 Node20 教程和参考项目保持一致。以后升级 Node 时，要把 Node、npm、TypeScript、类型包和测试工具作为一整套升级并重新验证，不能只随意升级其中一个包。

先检查当前环境：

```powershell
node --version
npm --version
```

预期分别显示：

```text
v20.15.0
10.7.0
```

在项目根目录新建 `.node-version`：

```text
20.15.0
```

它用于告诉支持该文件的 Node 版本管理工具：这个项目需要 Node 20.15.0。

再新建 `.npmrc`：

```ini

engine-strict=true
```

- `save-exact=true`：以后安装依赖时，默认写入精确版本，不自动添加 `^`；
- `engine-strict=true`：当前 Node/npm 不满足 `package.json` 的 engines 时，安装直接失败。

在项目根目录执行：

```powershell

npm install --save-exact express@5.2.1 mysql2@3.23.2 dotenv@17.4.2
```

安装后，确认 `package.json` 中的直接依赖没有 `^` 或 `~`，并补充 Node/npm 约束和脚本：

```json
{
  "type": "module",
  "packageManager": "npm@10.7.0",
  "engines": {
    "node": "20.15.0",
    "npm": "10.7.0"
  },
  "scripts": {
    "dev": "node --watch src/app.js",
    "start": "node src/app.js"
  },
  "dependencies": {
    "dotenv": "17.4.2",
    "express": "5.2.1",
    "mysql2": "3.23.2"
  }

```

这里展示的是需要加入或确认的字段，不要删除 `package.json` 自动生成的其他字段。

`npm install` 会同时生成 `package-lock.json`。必须把它提交到 Git，因为：

```text
package.json       锁定你直接声明的依赖版本
package-lock.json  锁定完整依赖树，包括依赖的依赖
```

克隆项目或在 CI 中安装时，不要重新解析版本范围，统一执行：


`npm ci` 会严格按照 `package-lock.json` 安装；如果锁文件与 `package.json` 不一致，它会直接失败，不会悄悄改锁文件。

只有在你明确决定增加或升级依赖时才执行 `npm install --save-exact 包名@精确版本`，并同时审查 `package.json` 和 `package-lock.json` 的变化。

## 2. 第一阶段：一个文件，一个 app.post

### 2.1 这一阶段只学什么

第一阶段只学习：一个请求从进入 Express 到写入 MySQL，完整发生了什么。

暂时不要考虑：

- Service；
- Repository；
- class；
- interface；
- DTO；
- 依赖注入；
- 多文件目录。

新建 `src/app.js`，完整代码如下：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

app.post('/users', async (req, res, next) => {
  try {
    const rawName = req.body?.name
    const rawEmail = req.body?.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const name = rawName.trim()
    const email = rawEmail.trim().toLowerCase()

    if (name.length < 2 || name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const [existingRows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    if (existingRows.length > 0) {
      res.status(409).json({
        success: false,
        code: 'EMAIL_ALREADY_EXISTS',
        message: '该邮箱已被使用'
      })
      return
    }

    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [name, email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        res.status(409).json({
          success: false,
          code: 'EMAIL_ALREADY_EXISTS',
          message: '该邮箱已被使用'
        })
        return
      }
      throw error
    }

    const [createdRows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [insertResult.insertId]
    )

    const createdUser = createdRows[0]

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: {
        id: Number(createdUser.id),
        name: createdUser.name,
        email: createdUser.email,
        createdAt: createdUser.created_at
      }
    })
  } catch (error) {
    next(error)
  }
})

app.use((error, _req, res, _next) => {
  console.error('未处理的请求异常', error)

  res.status(500).json({
    success: false,
    code: 'INTERNAL_SERVER_ERROR',
    message: '服务器内部错误'
  })
})

const port = Number(process.env.PORT ?? 3000)

app.listen(port, () => {
  console.log(`服务已启动：http://localhost:${port}`)
})
```

### 2.2 不要嫌它长，先顺着读

现在一个文件确实比较长，但业务流程完全暴露在眼前：

```text
读取 req.body
  ↓
检查 name 和 email
  ↓
清洗 name 和 email
  ↓
SELECT 检查邮箱
  ↓
INSERT 创建用户
  ↓
SELECT 读取创建结果
  ↓
返回 HTTP 201
```

此时你不需要打开其他文件，也不会因为 import 跳来跳去。

第一阶段必须先回答这些问题：

- `express.json()` 为什么必须在路由前？
- 为什么先 `trim()` 再判断长度？
- 为什么邮箱转成小写？
- SQL 中的 `?` 对应哪个参数？
- 为什么查重后仍然捕获 `ER_DUP_ENTRY`？
- 为什么创建成功返回 201？

如果这些问题还说不清楚，不要进入第二阶段。

### 2.3 运行和请求

启动：

```powershell
npm run dev
```

请求：

```powershell
$body = @{
  name = '  张三  '
  email = ' ZhangSan@Example.COM '
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri 'http://localhost:3000/users' `
  -ContentType 'application/json' `
  -Body $body
```

你应该看到 HTTP 201，名字被去掉首尾空格，邮箱变为小写。

### 2.4 为什么要进入第二阶段

当你想增加“注册用户”和“管理员创建用户”两个入口时，两个 Route 都需要重复：

```text
查邮箱
创建用户
处理重复邮箱
```

这部分不是 HTTP 控制，而是“创建用户”业务。此时才有真实理由抽 Service。

## 3. 第二阶段：只抽一个 createUser Service 函数

### 3.1 这一阶段只改变什么

只做一件事：把“查重和创建”移动到 `createUser(input)`。

仍然保持：

- 只有一个 `src/app.js`；
- 不创建 Service 文件夹；
- 不创建 Repository；
- 不使用 class；
- 不写 TypeScript interface。

完整 `src/app.js`：


### 3.2 Route 和 Service 函数现在分别做什么

Route：

```text
读取 HTTP 请求
校验并清洗 HTTP 参数
调用 createUser
选择 HTTP 201
```

`createUser`：

```text
检查邮箱是否存在
创建用户
把重复邮箱表达为业务错误
返回创建结果
```

你已经有了 Service，但它还不是 class，也没有单独文件。

### 3.3 为什么 Service 仍然直接写 SQL

这是故意的。

本阶段只学习“HTTP 控制”和“创建用户业务”分开。如果同时再引入 Repository，你很难判断到底是哪次拆分帮助了你。

当 Service 里只有少量 SQL 时，先放着并不会妨碍学习。

### 3.4 为什么进入第三阶段

当你准备测试 `createUser()` 时，会发现它内部固定使用真实 `pool`：

```js
await pool.execute('SQL', [参数])
```

这意味着：

- 测试业务规则必须启动 MySQL；
- SQL 和业务判断混在同一个函数；
- 以后换数据来源需要修改 Service。

这时才有真实理由抽 Repository。

## 4. 第三阶段：抽 Repository 对象，但仍在一个文件

### 4.1 这一阶段只改变什么

只把数据库操作集中到：

```js
const userRepository = {
  findByEmail,
  findById,
  create
}
```

Service 不再出现 SQL，但所有代码仍在同一个 `src/app.js` 中。

完整代码：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function emailAlreadyExistsError() {
  const error = new Error('该邮箱已被使用')
  error.code = 'EMAIL_ALREADY_EXISTS'
  return error
}

const userRepository = {
  async findByEmail(email) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ?? null
  },

  async findById(id) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ?? null
  },

  async create(input) {
    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        throw emailAlreadyExistsError()
      }
      throw error
    }

    const createdRow = await userRepository.findById(insertResult.insertId)

    if (!createdRow) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return {
      id: Number(createdRow.id),
      name: createdRow.name,
      email: createdRow.email,
      createdAt: createdRow.created_at
    }
  }
}

async function createUser(input) {
  const existingUser = await userRepository.findByEmail(input.email)

  if (existingUser) {
    throw emailAlreadyExistsError()
  }

  return userRepository.create(input)
}

app.post('/users', async (req, res, next) => {
```

### 4.2 现在的主线

```text
app.post
  ↓
createUser(input)
  ↓
userRepository.findByEmail(email)
  ↓
userRepository.create(input)
  ↓
MySQL
```

这就是最容易理解的三层雏形：

```text
HTTP → 业务 → 数据库
```

### 4.3 Repository 解决了什么

Service 现在只表达业务：

```js
const existingUser = await userRepository.findByEmail(input.email)

if (existingUser) {
  throw emailAlreadyExistsError()
}

return userRepository.create(input)
```

Service 不再关心：

- 表名；
- SELECT 字段；
- INSERT 语法；
- mysql2 返回数组的形式；
- `insertId` 怎么读取。

### 4.4 为什么还不使用 class

当前只有一个 `createUser()`，普通函数足够清晰。为了“看起来像 Java”而立即改成 class，没有带来明显收益。

当 User 开始有多个用例，所有用例都需要同一个 Repository 时，class 才开始方便。

## 5. 第四阶段：把 Service 改成 class

### 5.1 class 在这里解决什么问题

假设以后增加：

```text
create
getById
list
remove
```

这些用例都需要 `userRepository`。可以把共同依赖通过构造器传入一次：

```js
class UserService {
  constructor(repository) {
    this.repository = repository
  }
}
```

完整 `src/app.js`：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function emailAlreadyExistsError() {
  const error = new Error('该邮箱已被使用')
  error.code = 'EMAIL_ALREADY_EXISTS'
  return error
}

const userRepository = {
  async findByEmail(email) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ?? null
  },

  async findById(id) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ?? null
  },

  async create(input) {
    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        throw emailAlreadyExistsError()
      }
      throw error
    }

    const createdRow = await userRepository.findById(insertResult.insertId)

    if (!createdRow) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return {
      id: Number(createdRow.id),
      name: createdRow.name,
      email: createdRow.email,
      createdAt: createdRow.created_at
    }
  }
}

class UserService {
  constructor(repository) {
    this.repository = repository
  }

  async create(input) {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw emailAlreadyExistsError()
    }

    return this.repository.create(input)
  }
}

app.post('/users', async (req, res, next) => {
  try {
    const rawName = req.body?.name
    const rawEmail = req.body?.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const name = rawName.trim()
    const email = rawEmail.trim().toLowerCase()

    if (name.length < 2 || name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const user = await userService.create({ name, email })

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: user
    })
  } catch (error) {
    next(error)
  }
})

app.use((error, _req, res, _next) => {
  if (error?.code === 'EMAIL_ALREADY_EXISTS') {
    res.status(409).json({
      success: false,
      code: error.code,
      message: error.message

    return

})
```

### 5.2 constructor(repository) 就是依赖注入

重点不是 class 关键字，重点是这行：

```js
const userService = new UserService(userRepository)
```

Service 没有在内部写：

```js
this.repository = userRepository
```

也没有自己创建 MySQL Pool。外部把依赖交给它，这就叫依赖注入。

测试时可以传另一个对象：

```js
const fakeRepository = {
  async findByEmail() {
    return null
  },
  async create(input) {
    return {
      id: 1,
      name: input.name,
      email: input.email,
      createdAt: new Date('2026-08-05T08:00:00.000Z')
    }
  }
}

const serviceForTest = new UserService(fakeRepository)
```

### 5.3 class 不会自动让代码更高级

如果只有一个简单函数，class 可能只是增加写法。只有当它带来以下收益时才值得使用：

- 多个方法共享同一组依赖；
- 需要清晰的构造器注入；
- 需要在测试中替换依赖；
- 需要保存与用例有关的配置。

### 5.4 为什么进入第五阶段

JavaScript 允许传入任何形状的 Repository：

```js
new UserService({ wrongMethod() {} })
```

程序只有运行到 `findByEmail()` 时才报错。

当你已经理解 Route、Service、Repository 和注入关系，再让 TypeScript 检查契约，这时类型是在帮助你，而不是用十几个陌生名字淹没你。

### 6.2 完整 app.ts

```ts
import 'dotenv/config'
import express, { type ErrorRequestHandler } from 'express'
import mysql, {
  type Pool,
  type ResultSetHeader,
  type RowDataPacket
} from 'mysql2/promise'

interface CreateUserBody {
  name?: unknown
  email?: unknown
}

type CreateUserDto = {
  name: string
  email: string
}

interface User {
  id: number
  name: string
  email: string
  createdAt: Date
}

interface UserOutput {
  id: number
  name: string
  email: string
  createdAt: string
}

interface UserRepository {
  findByEmail(email: string): Promise<User | null>
  create(input: CreateUserDto): Promise<User>
}

interface UserRow extends RowDataPacket {
  id: number | string
  name: string
  email: string
  created_at: Date | string
}

interface MysqlErrorLike {
  code?: unknown
}

class EmailAlreadyExistsError extends Error {
  readonly statusCode = 409
  readonly code = 'EMAIL_ALREADY_EXISTS'

  constructor() {
    super('该邮箱已被使用')
    this.name = 'EmailAlreadyExistsError'
  }
}

class DuplicateUserEmailError extends Error {
  constructor() {
    super('Duplicate user email')
    this.name = 'DuplicateUserEmailError'
  }
}

function isValidEmail(value: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function isDuplicateEntry(error: unknown): boolean {
  return (
    typeof error === 'object' &&
    error !== null &&
    (error as MysqlErrorLike).code === 'ER_DUP_ENTRY'
  )
}

function toUser(row: UserRow): User {
  const id = Number(row.id)
  const createdAt =
    row.created_at instanceof Date
      ? row.created_at
      : new Date(row.created_at)

  if (!Number.isSafeInteger(id)) {
    throw new Error(`用户ID超出JavaScript安全整数范围：${String(row.id)}`)
  }

  if (Number.isNaN(createdAt.getTime())) {
    throw new Error(`数据库返回了无效时间：${String(row.created_at)}`)
  }

  return {
    id,
    name: row.name,
    email: row.email,
    createdAt
  }
}

class MysqlUserRepository implements UserRepository {
  constructor(private readonly pool: Pool) {}

  async findByEmail(email: string): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ? toUser(rows[0]) : null
  }

  private async findById(id: number): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ? toUser(rows[0]) : null
  }

  async create(input: CreateUserDto): Promise<User> {
    let insertResult: ResultSetHeader

    try {
      const [result] = await this.pool.execute<ResultSetHeader>(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (isDuplicateEntry(error)) {
        throw new DuplicateUserEmailError()
      }
      throw error
    }

    const createdUser = await this.findById(insertResult.insertId)

    if (!createdUser) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return createdUser
  }
}

class UserService {
  constructor(private readonly repository: UserRepository) {}

  async create(input: CreateUserDto): Promise<UserOutput> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new EmailAlreadyExistsError()
    }

    try {
      const user = await this.repository.create(input)

      return {
        id: user.id,
        name: user.name,
        email: user.email,
        createdAt: user.createdAt.toISOString()
      }
    } catch (error) {
      if (error instanceof DuplicateUserEmailError) {
        throw new EmailAlreadyExistsError()
      }
      throw error
    }
  }
}

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

const userRepository: UserRepository = new MysqlUserRepository(pool)
const userService = new UserService(userRepository)
const app = express()

app.use(express.json())

app.post('/users', async (req, res, next) => {
  try {
    const body = req.body as CreateUserBody
    const rawName = body.name
    const rawEmail = body.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const input: CreateUserDto = {
      name: rawName.trim(),
      email: rawEmail.trim().toLowerCase()
    }

    if (input.name.length < 2 || input.name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(input.email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const user = await userService.create(input)

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: user
    })
  } catch (error) {
    next(error)
  }
})

const errorHandler: ErrorRequestHandler = (
  error,
  _req,
  res,
  _next
) => {
  if (error instanceof EmailAlreadyExistsError) {
    res.status(error.statusCode).json({
      success: false,
      code: error.code,
      message: error.message
    })
    return
  }

  console.error('未处理的请求异常', error)

  res.status(500).json({
    success: false,
    code: 'INTERNAL_SERVER_ERROR',
    message: '服务器内部错误'
  })
}

app.use(errorHandler)

const port = Number(process.env.PORT ?? 3000)

app.listen(port, () => {
  console.log(`服务已启动：http://localhost:${port}`)
})
```

### 6.3 现在类型分别帮助了什么

`CreateUserDto`：

```ts
type CreateUserDto = {
  name: string
  email: string
}
```

它规定 Service 的合法输入。Route 完成运行时校验后，才构造这个 DTO。

`UserRepository`：

```ts
interface UserRepository {
  findByEmail(email: string): Promise<User | null>
  create(input: CreateUserDto): Promise<User>
}
```

它规定 Service 需要的数据能力。传入缺少 `findByEmail` 的对象时，TypeScript 在启动前就会报错。

`User`：

```ts
interface User {
  id: number
  name: string
  email: string
  createdAt: Date
}
```

它表示程序内部的用户，不带 Express Request，也不继承 MySQL Row。

`UserOutput`：

```ts
interface UserOutput {
  id: number
  name: string
  email: string
  createdAt: string
}
```

它表示允许返回给客户端的数据，日期已经转换为字符串。

### 6.4 为什么类型最后学更容易

现在看到：

```ts
constructor(private readonly repository: UserRepository) {}
```

你已经知道它的真实含义：

```text
Service 需要一个能 findByEmail 和 create 的对象。
```

类型只是把你已经理解的关系写给编译器检查，而不是凭空增加一层抽象。

执行：

```powershell
npm run typecheck
npm run dev
```

## 8. 五个阶段到底增加了什么

| 阶段 | 新增概念 | 解决的问题 | 仍然故意不做 |
|---|---|---|---|
| 一 | 完整 HTTP 流程 | 看见业务全貌 | 不分层 |
| 二 | Service 函数 | HTTP 与业务分开 | Service 仍写 SQL |
| 三 | Repository 对象 | 业务与 SQL 分开 | 不使用 class 和接口 |
| 四 | class + 构造器注入 | 多方法共享依赖、方便替换 | 不加 TypeScript 类型 |
| 五 | DTO + Repository interface | 编译阶段检查契约 | 暂时不细拆十个文件 |

注意：后一个阶段不是在否定前一个阶段。

每个阶段都是在代码出现真实痛点后，增加恰好足够的结构。

---

## 9. 什么时候进入下一阶段

### 停在第一阶段

适合：

- 刚学 Express；
- 还不熟悉 req、res、next；
- 还不能独立写出一次 SELECT 和 INSERT；
- 练习代码只有一个接口。

目标不是目录漂亮，而是能不看教程写出：校验、查重、创建、返回。

### 进入第二阶段

当你能指出哪些代码是 HTTP 控制，哪些代码是创建用户业务时，抽 Service 函数。

### 进入第三阶段

当 Service 中的 SQL 妨碍阅读或测试时，抽 Repository 对象。

### 进入第四阶段

当多个 User 用例需要共享同一个 Repository 时，使用 class 和构造器注入。

### 进入第五阶段

当你已经理解对象之间的调用关系，开始需要编译器检查输入、输出和依赖契约时，加入 TypeScript 类型。

### 进入生产版细分

当模块出现多个接口、多种 DTO、内部 Entity、多个数据源、复杂 Mapper 和多人协作时，再细拆文件。

## 10. 初学者最容易犯的学习错误

### 错误一：按文件名逐个硬啃

看到十个文件后，从 entity 开始读，再读 dto、schema、mapper，最后忘了接口究竟要做什么。

正确方式：先从一次 HTTP 请求开始，沿函数调用向下跟。

### 错误二：还没遇到问题就抽象

只有一个接口时，就创建通用 BaseRepository、AbstractService、DI Container。

正确方式：先写出重复或耦合，再抽取能解决它的最小结构。

### 错误三：把 class 当成分层

把一个函数包进 class，但 Service 仍然读取 `req.body`、返回 `res.json()`、执行 SQL。这不叫职责分离，只是换了语法。

### 错误四：把文件多当成生产级

生产级不等于文件多。生产级首先是：

- 数据正确；
- 输入可靠；
- SQL 安全；
- 错误可控；
- 代码可测试；
- 能稳定部署和排查。

### 错误五：一次重构十个文件

一次改 Route、Controller、Service、Repository、DTO、Mapper，出错后不知道是哪一步造成的。

正确方式：一次只移动一个职责，验证成功再继续。

## 11. 最终应该记住的不是目录，而是演进原因

把五个阶段压缩成五句话：

```text
第一阶段：先看懂整个创建用户流程。
第二阶段：HTTP 代码太杂，所以抽 Service。
第三阶段：Service 被 SQL 淹没，所以抽 Repository。
第四阶段：多个用例共享依赖，所以使用 class 和构造器注入。
第五阶段：调用关系已经理解，所以加入 DTO 和 Repository 接口让编译器检查。
```

最终生产结构只是第五阶段继续发展的结果：

```text
Route → Controller → Service → Repository → MySQL
```

这个箭头从第一阶段就已经存在，只是最开始全部写在一个函数里。

因此，不要继续按照复杂项目的文件顺序硬啃。回到第一阶段，亲手写完一个 `app.post('/users')`；确认自己看得见业务，再进入下一阶段。
