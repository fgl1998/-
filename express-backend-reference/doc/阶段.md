# Express 接口学习阶段：从一个函数逐步演进到分层架构

## 0. 先纠正学习顺序

这套生产级项目架构对大型 Express 项目有价值，但它不适合作为初学者的第一站。

如果一开始就同时看到：

```text
schema
dto
entity
controller
service
repository interface
mysql repository
mapper
route
module
```

注意力很容易全部耗在这些问题上：

- 这个类型从哪个文件导入？
- 为什么这里又跳到另一个文件？
- Entity、DTO、Row 有什么区别？
- 为什么一个创建用户接口需要打开十个标签页？

结果是真正的业务流程反而看不见了。

正确的学习方式应该反过来：先把业务流程放在眼前，确认自己能完整理解，再根据代码出现的真实问题逐步拆分。

这篇教程只学习一个接口：

```http
POST /users
```

始终只有四个业务动作：

```text
校验输入
  ↓
检查邮箱是否重复
  ↓
创建用户
  ↓
返回结果
```

我们分五个阶段学习：

```text
阶段一：所有逻辑都在 app.post 中
阶段二：抽出 createUser Service 函数
阶段三：抽出 Repository 对象
阶段四：把 Service 改成 class，并注入 Repository
阶段五：最后加入 TypeScript DTO 和 Repository 接口
```

阶段一到阶段四始终修改同一个 `src/app.js`。不要每学一个概念就立刻增加目录和文件。

## 1. 公共准备：MySQL、依赖和环境变量

### 1.1 安装依赖

这篇教程固定使用同一套版本，避免你今天和一个月后安装出不同结果：

```text

mysql2    3.23.2
```

这里选择 Node 20.15.0，是为了与现有 Node20 教程和参考项目保持一致。以后升级 Node 时，要把 Node、npm、TypeScript、类型包和测试工具作为一整套升级并重新验证，不能只随意升级其中一个包。

先检查当前环境：

```powershell
node --version
npm --version
```

预期分别显示：

```text

10.7.0
```

```text

```

它用于告诉支持该文件的 Node 版本管理工具：这个项目需要 Node 20.15.0。


- `engine-strict=true`：当前 Node/npm 不满足 `package.json` 的 engines 时，安装直接失败。

在项目根目录执行：

```powershell

```

安装后，确认 `package.json` 中的直接依赖没有 `^` 或 `~`，并补充 Node/npm 约束和脚本：

```json
{

  "packageManager": "npm@10.7.0",
  "engines": {
    "node": "20.15.0",
    "npm": "10.7.0"
  },
  "scripts": {
    "dev": "node --watch src/app.js",
    "start": "node src/app.js"
  },
  "dependencies": {
    "dotenv": "17.4.2",
```

这里展示的是需要加入或确认的字段，不要删除 `package.json` 自动生成的其他字段。

`npm install` 会同时生成 `package-lock.json`。必须把它提交到 Git，因为：

```text

package-lock.json  锁定完整依赖树，包括依赖的依赖
```

`npm ci` 会严格按照 `package-lock.json` 安装；如果锁文件与 `package.json` 不一致，它会直接失败，不会悄悄改锁文件。

只有在你明确决定增加或升级依赖时才执行 `npm install --save-exact 包名@精确版本`，并同时审查 `package.json` 和 `package-lock.json` 的变化。

## 2. 第一阶段：一个文件，一个 app.post

### 2.1 这一阶段只学什么

第一阶段只学习：一个请求从进入 Express 到写入 MySQL，完整发生了什么。

暂时不要考虑：

- Service；
- Repository；
- class；
- interface；
- DTO；
- 依赖注入；
- 多文件目录。

新建 `src/app.js`，完整代码如下：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

app.post('/users', async (req, res, next) => {
  try {
    const rawName = req.body?.name
    const rawEmail = req.body?.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const name = rawName.trim()
    const email = rawEmail.trim().toLowerCase()

    if (name.length < 2 || name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const [existingRows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    if (existingRows.length > 0) {
      res.status(409).json({
        success: false,
        code: 'EMAIL_ALREADY_EXISTS',
        message: '该邮箱已被使用'
      })
      return
    }

    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [name, email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        res.status(409).json({
          success: false,
          code: 'EMAIL_ALREADY_EXISTS',
          message: '该邮箱已被使用'
        })
        return
      }
      throw error
    }

    const [createdRows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [insertResult.insertId]
    )

    const createdUser = createdRows[0]

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: {
        id: Number(createdUser.id),
        name: createdUser.name,
        email: createdUser.email,
        createdAt: createdUser.created_at
      }
    })
  } catch (error) {
    next(error)
  }
})

app.use((error, _req, res, _next) => {
  console.error('未处理的请求异常', error)

  res.status(500).json({
    success: false,
    code: 'INTERNAL_SERVER_ERROR',
    message: '服务器内部错误'
  })
})

const port = Number(process.env.PORT ?? 3000)

app.listen(port, () => {
  console.log(`服务已启动：http://localhost:${port}`)
})
```

### 2.2 不要嫌它长，先顺着读

现在一个文件确实比较长，但业务流程完全暴露在眼前：

```text
读取 req.body
  ↓
检查 name 和 email
  ↓
清洗 name 和 email
  ↓
SELECT 检查邮箱
  ↓
INSERT 创建用户
  ↓
SELECT 读取创建结果
  ↓
返回 HTTP 201
```

此时你不需要打开其他文件，也不会因为 import 跳来跳去。

第一阶段必须先回答这些问题：

- `express.json()` 为什么必须在路由前？
- 为什么先 `trim()` 再判断长度？
- 为什么邮箱转成小写？
- SQL 中的 `?` 对应哪个参数？
- 为什么查重后仍然捕获 `ER_DUP_ENTRY`？
- 为什么创建成功返回 201？

如果这些问题还说不清楚，不要进入第二阶段。

### 2.3 运行和请求

启动：

```powershell
npm run dev
```

请求：

```powershell
$body = @{
  name = '  张三  '
  email = ' ZhangSan@Example.COM '
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri 'http://localhost:3000/users' `
  -ContentType 'application/json' `
  -Body $body
```

你应该看到 HTTP 201，名字被去掉首尾空格，邮箱变为小写。

### 2.4 为什么要进入第二阶段

当你想增加“注册用户”和“管理员创建用户”两个入口时，两个 Route 都需要重复：

```text
查邮箱
创建用户
处理重复邮箱
```

这部分不是 HTTP 控制，而是“创建用户”业务。此时才有真实理由抽 Service。

## 3. 第二阶段：只抽一个 createUser Service 函数

### 3.1 这一阶段只改变什么

只做一件事：把“查重和创建”移动到 `createUser(input)`。

仍然保持：

- 只有一个 `src/app.js`；
- 不创建 Service 文件夹；
- 不创建 Repository；
- 不使用 class；
- 不写 TypeScript interface。

完整 `src/app.js`：


### 3.2 Route 和 Service 函数现在分别做什么

Route：

```text
读取 HTTP 请求
校验并清洗 HTTP 参数
调用 createUser
选择 HTTP 201
```

`createUser`：

```text
检查邮箱是否存在
创建用户
把重复邮箱表达为业务错误
返回创建结果
```

你已经有了 Service，但它还不是 class，也没有单独文件。

### 3.3 为什么 Service 仍然直接写 SQL

这是故意的。

本阶段只学习“HTTP 控制”和“创建用户业务”分开。如果同时再引入 Repository，你很难判断到底是哪次拆分帮助了你。

当 Service 里只有少量 SQL 时，先放着并不会妨碍学习。

### 3.4 为什么进入第三阶段

当你准备测试 `createUser()` 时，会发现它内部固定使用真实 `pool`：

```js
await pool.execute('SQL', [参数])
```

这意味着：

- 测试业务规则必须启动 MySQL；
- SQL 和业务判断混在同一个函数；
- 以后换数据来源需要修改 Service。

这时才有真实理由抽 Repository。

## 4. 第三阶段：抽 Repository 对象，但仍在一个文件

### 4.1 这一阶段只改变什么

只把数据库操作集中到：

```js
const userRepository = {
  findByEmail,
  findById,
  create
}
```

Service 不再出现 SQL，但所有代码仍在同一个 `src/app.js` 中。

完整代码：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function emailAlreadyExistsError() {
  const error = new Error('该邮箱已被使用')
  error.code = 'EMAIL_ALREADY_EXISTS'
  return error
}

const userRepository = {
  async findByEmail(email) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ?? null
  },

  async findById(id) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ?? null
  },

  async create(input) {
    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        throw emailAlreadyExistsError()
      }
      throw error
    }

    const createdRow = await userRepository.findById(insertResult.insertId)

    if (!createdRow) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return {
      id: Number(createdRow.id),
      name: createdRow.name,
      email: createdRow.email,
      createdAt: createdRow.created_at
    }
  }
}

async function createUser(input) {
  const existingUser = await userRepository.findByEmail(input.email)

  if (existingUser) {
    throw emailAlreadyExistsError()
  }

  return userRepository.create(input)
}
```

### 4.2 现在的主线

```text
app.post
  ↓
createUser(input)
  ↓
userRepository.findByEmail(email)
  ↓
userRepository.create(input)
  ↓
MySQL
```

这就是最容易理解的三层雏形：

```text
HTTP → 业务 → 数据库
```

### 4.3 Repository 解决了什么

Service 现在只表达业务：

```js
const existingUser = await userRepository.findByEmail(input.email)

if (existingUser) {
  throw emailAlreadyExistsError()
}

return userRepository.create(input)
```

Service 不再关心：

- 表名；
- SELECT 字段；
- INSERT 语法；
- mysql2 返回数组的形式；
- `insertId` 怎么读取。

### 4.4 为什么还不使用 class

当前只有一个 `createUser()`，普通函数足够清晰。为了“看起来像 Java”而立即改成 class，没有带来明显收益。

当 User 开始有多个用例，所有用例都需要同一个 Repository 时，class 才开始方便。

---

## 5. 第四阶段：把 Service 改成 class

### 5.1 class 在这里解决什么问题

假设以后增加：

```text
create
getById
list
remove
```

这些用例都需要 `userRepository`。可以把共同依赖通过构造器传入一次：

```js
class UserService {
  constructor(repository) {
    this.repository = repository
  }
}
```

完整 `src/app.js`：

```js
import 'dotenv/config'
import express from 'express'
import mysql from 'mysql2/promise'

const app = express()

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

app.use(express.json())

function isValidEmail(value) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function emailAlreadyExistsError() {
  const error = new Error('该邮箱已被使用')
  error.code = 'EMAIL_ALREADY_EXISTS'
  return error
}

const userRepository = {
  async findByEmail(email) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ?? null
  },

  async findById(id) {
    const [rows] = await pool.execute(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ?? null
  },

  async create(input) {
    let insertResult

    try {
      const [result] = await pool.execute(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (error?.code === 'ER_DUP_ENTRY') {
        throw emailAlreadyExistsError()
      }
      throw error
    }

    const createdRow = await userRepository.findById(insertResult.insertId)

    if (!createdRow) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return {
      id: Number(createdRow.id),
      name: createdRow.name,
      email: createdRow.email,
      createdAt: createdRow.created_at
    }
  }
}

class UserService {
  constructor(repository) {
    this.repository = repository
  }

  async create(input) {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw emailAlreadyExistsError()
    }

    return this.repository.create(input)
  }
}

const userService = new UserService(userRepository)

app.post('/users', async (req, res, next) => {
  try {
    const rawName = req.body?.name
    const rawEmail = req.body?.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const name = rawName.trim()
    const email = rawEmail.trim().toLowerCase()

    if (name.length < 2 || name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const user = await userService.create({ name, email })

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: user
    })
  } catch (error) {
    next(error)
  }
})

app.use((error, _req, res, _next) => {
  if (error?.code === 'EMAIL_ALREADY_EXISTS') {
    res.status(409).json({
      success: false,
      code: error.code,
      message: error.message
    })
    return
  }

  console.error('未处理的请求异常', error)

  res.status(500).json({
    success: false,
    code: 'INTERNAL_SERVER_ERROR',
    message: '服务器内部错误'
  })
})

const port = Number(process.env.PORT ?? 3000)

app.listen(port, () => {
  console.log(`服务已启动：http://localhost:${port}`)
})
```

### 5.2 constructor(repository) 就是依赖注入

重点不是 class 关键字，重点是这行：

```js
const userService = new UserService(userRepository)
```

Service 没有在内部写：

```js
this.repository = userRepository
```

也没有自己创建 MySQL Pool。外部把依赖交给它，这就叫依赖注入。

测试时可以传另一个对象：

```js
const fakeRepository = {
  async findByEmail() {
    return null
  },
  async create(input) {
    return {
      id: 1,
      name: input.name,
      email: input.email,
      createdAt: new Date('2026-08-05T08:00:00.000Z')
    }
  }
}

const serviceForTest = new UserService(fakeRepository)
```

### 5.3 class 不会自动让代码更高级

如果只有一个简单函数，class 可能只是增加写法。只有当它带来以下收益时才值得使用：

- 多个方法共享同一组依赖；
- 需要清晰的构造器注入；
- 需要在测试中替换依赖；
- 需要保存与用例有关的配置。

### 5.4 为什么进入第五阶段

JavaScript 允许传入任何形状的 Repository：

```js
new UserService({ wrongMethod() {} })
```

程序只有运行到 `findByEmail()` 时才报错。

当你已经理解 Route、Service、Repository 和注入关系，再让 TypeScript 检查契约，这时类型是在帮助你，而不是用十几个陌生名字淹没你。

## 6. 第五阶段：TypeScript 分四小步，不一次吃完

第五阶段不是必须马上完成的阶段。

如果第四阶段的 JavaScript 版本已经能满足你的学习目标，可以先停在那里，继续用 JavaScript 写查询、修改和删除接口。等 Route、Service、Repository 的调用关系已经很熟，再回来学习 TypeScript。

不要把 TypeScript 理解成“小型 Java”。TypeScript 类型主要存在于编译阶段，编译成 JavaScript 后大部分都会消失。它能检查程序内部的调用，但不能自动证明 HTTP 请求和数据库数据在运行时一定正确。

先把项目分成两个区域：

```text
不可信边界
req.body、req.params、process.env、MySQL Row
        ↓ 运行时校验和转换
可信业务区域
CreateUserInput、User、UserService
```

不确定性无法完全消灭。合理目标是把它限制在 HTTP、环境变量和数据库边界，不让它进入 Service。

### 6.1 第 5A 步：只给 Service 输入和输出加类型

第一步只学习两个对象类型：

```ts
type CreateUserInput = {
  name: string
  email: string
}

type User = {
  id: number
  name: string
  email: string
  createdAt: Date
}
```

然后只给 Service 的参数和返回值加类型：

```ts
class UserService {
  constructor(private readonly repository: any) {}

  async create(input: CreateUserInput): Promise<User> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new Error('该邮箱已被使用')
    }

    return this.repository.create(input)
  }
}
```

此时临时使用 `repository: any` 是有意的教学过渡，不是最终生产写法。

本小步只需要理解：

```text
input: CreateUserInput
```

表示函数只接受具有 `name` 和 `email` 的输入。

```text
Promise<User>
```

表示异步函数最终返回一个 `User`。

如果这两个概念还不自然，就停在 5A，不要继续加 Repository 类型。

### 6.2 第 5B 步：再给 Repository 加一个简单契约

等 5A 已经理解，再把 `any` 替换成：

```ts
type UserRepository = {
  findByEmail(email: string): Promise<User | null>
  create(input: CreateUserInput): Promise<User>
}
```

Service 只改构造器类型：

```ts
class UserService {
  constructor(private readonly repository: UserRepository) {}

  async create(input: CreateUserInput): Promise<User> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new Error('该邮箱已被使用')
    }

    return this.repository.create(input)
  }
}
```

把 `UserRepository` 翻译成中文即可：

```text
UserService 需要一个对象。
这个对象必须有 findByEmail 和 create 两个方法。
```

TypeScript 使用结构类型。对象只要具有这些方法，就符合这个契约，不要求它一定通过某个 Java class 或构造器创建。

这一阶段统一使用 `type` 描述对象，暂时不讨论 `type` 和 `interface` 的细节差异。

### 6.3 第 5C 步：只在 HTTP 边界处理 unknown

HTTP 请求体来自客户端，运行时可能是任何内容。只有这个边界需要面对 `unknown`：

```ts
function parseCreateUserInput(
  body: unknown
): CreateUserInput | null {
  if (
    typeof body !== 'object' ||
    body === null ||
    !('name' in body) ||
    !('email' in body) ||
    typeof body.name !== 'string' ||
    typeof body.email !== 'string'
  ) {
    return null
  }

  const name = body.name.trim()
  const email = body.email.trim().toLowerCase()

  if (name.length < 2 || name.length > 50) {
    return null
  }

  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    return null
  }

  return { name, email }
}
```

#### 5C-1：先弄清楚 `userService` 是从哪里来的

下面 Route 中会出现这行代码：

```ts
const user = await userService.create(input)
```

这里的 `userService` **不是 Express 提供的，也不是 TypeScript 自动生成的**。它是我们在应用启动时，自己用 `new UserService(...)` 创建出来的对象。

先区分两个名字：

```ts
UserService // 类：规定这个对象有哪些属性和方法
userService // 实例：根据 UserService 类真正创建出来的对象
```

这和 Java 中的概念相同：

```java
UserService userService = new UserService(userRepository);
```

TypeScript 中对应的写法是：

```ts
const userService = new UserService(userRepository)
```

右边的 `new UserService(userRepository)` 负责创建对象，左边的 `userService` 变量负责保存这个对象。后面的 Route 才能通过这个变量调用 `create` 方法。

#### 5C-2：先写一个真正有 TypeScript 类型的 `userRepository`

不能把第四阶段的 JavaScript Repository 原样复制过来，然后直接传给现在的 `UserService`。下面这种写法有问题：

```ts
// 错误示例：没有声明它必须满足 UserRepository
const userRepository = {
  async findByEmail(email) {
    // email 会触发隐式 any
  },

  async create(input) {
    // input 会触发隐式 any
  }
}
```

在严格模式下，TypeScript 会报告：

```text
TS7006：参数 email 隐式具有 any 类型
TS7006：参数 input 隐式具有 any 类型
```

而且第四阶段的 MySQL 查询返回 `created_at`，`UserRepository` 契约要求返回 `createdAt`，直接传入还会报告：

```text
TS2345：userRepository 不能赋给 UserRepository
Property 'createdAt' is missing
```

为了让5C只学习“Repository 契约、Service 注入和 HTTP 的 `unknown`”，先使用一个可以通过严格类型检查的内存 Repository。5D 再把它替换成真正的 MySQL Repository：

> **不要混写两个阶段：**第四阶段的 MySQL Repository 是 JavaScript 写法；5C 的 Service 已经受 TypeScript 契约约束。把前者原样传给后者，就会得到你看到的类型错误。停在5C时，请使用下面的 TypeScript 内存实现；如果此时必须继续连接 MySQL，就直接进入5D，把 Repository 的 MySQL 行、插入结果和错误全部类型化。

```ts
// 用数组临时模拟数据库；数组里的每一项都必须是 User
const users: User[] = []

// 下一个用户ID从1开始
let nextUserId = 1

// 关键：明确声明这个对象必须满足 UserRepository 契约
const userRepository: UserRepository = {
  async findByEmail(email: string): Promise<User | null> {
    const user = users.find((item) => item.email === email)
    return user ?? null
  },

  async create(input: CreateUserInput): Promise<User> {
    const user: User = {
      id: nextUserId,
      name: input.name,
      email: input.email,
      createdAt: new Date()
    }

    nextUserId += 1
    users.push(user)
    return user
  }
}
```

这里确实是 TypeScript，证据不是 `const` 或 `new`。这两个关键字 JavaScript 也有。真正体现 TypeScript 的部分是：

```ts
const users: User[] = []
const userRepository: UserRepository = { ... }
email: string
Promise<User | null>
input: CreateUserInput
Promise<User>
const user: User = { ... }
```

其中最关键的一行是：

```ts
const userRepository: UserRepository = {
```

冒号后面的 `UserRepository` 会要求右边对象必须完整实现 `findByEmail` 和 `create`，并且参数、返回值都必须符合5B定义的契约。任何一个方法写错，`tsc` 都会立即报错。

现在才能安全地把这个对象传给 Service：

```ts
const userService = new UserService(userRepository)
```

此时的来源关系是：

```text
UserRepository 类型契约
        ↓ 约束
userRepository 内存实现
        ↓ 传入构造器
new UserService(userRepository)
        ↓ 得到
userService
        ↓ 被 Route 调用
userService.create(input)
```

这个内存 Repository 只是5C的教学实现：服务器重启后数组会清空，不能用于生产环境。它存在的目的，是在不引入 `RowDataPacket`、`ResultSetHeader` 等 mysql2 类型之前，先让整条 TypeScript 调用链能够正确编译。5D 会把它换成 MySQL 实现。

#### 5C-3：`userRepository` 是怎样进入 Service 的

回头看 `UserService`：

```ts
class UserService {
  constructor(private readonly repository: UserRepository) {}

  async create(input: CreateUserInput): Promise<User> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new Error('该邮箱已被使用')
    }

    return this.repository.create(input)
  }
}
```

下面这句初看可能比较难：

```ts
constructor(private readonly repository: UserRepository) {}
```

它是 TypeScript 的构造器参数属性简写，等价于下面这个更接近 Java 的完整版本：

```ts
class UserService {
  private readonly repository: UserRepository

  constructor(repository: UserRepository) {
    this.repository = repository
  }

  async create(input: CreateUserInput): Promise<User> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new Error('该邮箱已被使用')
    }

    return this.repository.create(input)
  }
}
```

因此，执行：

```ts
const userService = new UserService(userRepository)
```

时，实际发生的是：

```ts
this.repository = userRepository
```

所以 `create` 方法中的：

```ts
this.repository.findByEmail(input.email)
this.repository.create(input)
```

最终调用的都是刚才传进来的 `userRepository` 对象。

#### 5C-4：最后才注册 Route

完整的代码排列顺序应该是：

```ts
// 1. 定义类型
type CreateUserInput = {
  name: string
  email: string
}

// 2. 定义符合 UserRepository 契约的内存实现
const users: User[] = []
let nextUserId = 1

const userRepository: UserRepository = {
  async findByEmail(email: string): Promise<User | null> {
    return users.find((user) => user.email === email) ?? null
  },

  async create(input: CreateUserInput): Promise<User> {
    const user: User = {
      id: nextUserId++,
      name: input.name,
      email: input.email,
      createdAt: new Date()
    }

    users.push(user)
    return user
  }
}

// 3. 定义 UserService 类，然后创建 userService 实例
const userService = new UserService(userRepository)

// 4. 创建 Express 应用并注册中间件
const app = express()
app.use(express.json())

// 5. 注册 Route；这里可以使用上面已经创建的 userService
```

现在再看 Route：

```ts
app.post('/users', async (req, res, next) => {
  try {
    const input = parseCreateUserInput(req.body)

    if (!input) {
      res.status(400).json({
        success: false,
        code: 'VALIDATION_ERROR',
        message: '请求参数错误'
      })
      return
    }

    const user = await userService.create(input)

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: user
    })
  } catch (error) {
    next(error)
  }
})
```

当一个 `POST /users` 请求真正到达时，执行顺序是：

```text
parseCreateUserInput(req.body)
        ↓ 得到可信的 input
userService.create(input)
        ↓ 进入 UserService.create
this.repository.findByEmail(input.email)
        ↓ 查重
this.repository.create(input)
        ↓ 在5C的内存数组中创建用户
返回创建后的 user
        ↓
Route 发送 201 响应
```

注意，`app.post(...)` 是在应用启动时**注册处理函数**；里面的函数体不会立刻运行。只有客户端真的发送 `POST /users` 请求时，函数体才会运行，并使用启动阶段已经创建好的 `userService`。

关键点不是掌握所有 `unknown` 写法，而是记住边界：

```text
req.body 是不可信的 unknown
        ↓ parseCreateUserInput
input 是可信的 CreateUserInput
        ↓
Service 不再处理 unknown
```

不要在 Service 中到处写 `unknown`，也不要用 `as CreateUserInput` 假装完成校验。`as` 只影响编译器，不会在运行时检查数据。

### 6.4 第 5D 步：mysql2 类型最后学

5C 使用内存数组实现 `UserRepository`，目的是先把 TypeScript 契约、Service 和 HTTP 边界学清楚。5D 只做一件事：把内存 Repository 换成真正使用 mysql2 的 Repository。

这一节不要一次背下所有类型。按照下面的顺序逐个理解：

```text
运行时的 mysql
      ↓ createPool
只在编译期存在的 Pool 类型
      ↓ execute SELECT
UserRow[]
      ↓ execute INSERT
ResultSetHeader
      ↓ Mapper
User
```

#### 5D-1：先把一行 import 拆成两行

最终代码使用了下面这行导入：

```ts
import mysql, {
  type Pool,
  type ResultSetHeader,
  type RowDataPacket
} from 'mysql2/promise'
```

第一次看时，不要把它当成一种复杂的新语法。它等价于：

```ts
// 导入运行时真正存在的 mysql 对象
import mysql from 'mysql2/promise'

// 只导入 TypeScript 类型
import type {
  Pool,
  ResultSetHeader,
  RowDataPacket
} from 'mysql2/promise'
```

两组导入的区别：

| 名称 | 运行时存在吗 | 用途 |
|---|---:|---|
| `mysql` | 是 | 调用 `mysql.createPool()` |
| `Pool` | 否 | 描述连接池对象的类型 |
| `RowDataPacket` | 否 | 描述 SELECT 返回的数据行 |
| `ResultSetHeader` | 否 | 描述 INSERT、UPDATE、DELETE 的执行结果 |

例如：

```ts
const pool: Pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})
```

编译成 JavaScript 后，`: Pool` 和三个 `type` 导入都会消失，`mysql.createPool(...)` 会保留。可以先这样记：

```text
mysql：程序运行时要用
三个 type：写代码和执行 tsc 时要用
```

#### 5D-2：`Pool` 是什么

`Pool` 是 mysql2 提供的连接池类型。它描述连接池上有哪些方法，例如：

```ts
pool.execute(...)
pool.query(...)
pool.getConnection()
pool.end()
```

Java 中可以把它粗略类比成 `DataSource`。Repository 接收 `Pool`：

```ts
class MysqlUserRepository {
  private readonly pool: Pool

  constructor(pool: Pool) {
    this.pool = pool
  }
}
```

TypeScript 的简写版本是：

```ts
class MysqlUserRepository {
  constructor(private readonly pool: Pool) {}
}
```

两段代码含义相同。执行：

```ts
const userRepository = new MysqlUserRepository(pool)
```

就是把外面的连接池保存到：

```ts
this.pool
```

之后 Repository 的每个方法都能通过 `this.pool.execute(...)` 执行 SQL。

#### 5D-3：先看 `execute` 在 JavaScript 中实际返回什么

先暂时不看泛型：

```ts
const result = await pool.execute(
  'SELECT id, name FROM users'
)
```

`result` 不是单独的行数组，而是一个包含两项的数组：

```text
result[0]：SQL 的主要结果
result[1]：字段描述信息 FieldPacket[]
```

可以想象成：

```ts
const result = [rows, fields]
```

我们通常只关心第一项，所以使用数组解构：

```ts
const [rows] = await pool.execute(
  'SELECT id, name FROM users'
)
```

它等价于：

```ts
const result = await pool.execute(
  'SELECT id, name FROM users'
)

const rows = result[0]
```

这里的方括号不是“数组类型”，而是 JavaScript 的数组解构语法。

#### 5D-4：为什么定义 `UserRow`

数据库中的列名是：

```text
id
name
email
created_at
```

因此，一条 SELECT 结果行的形状是：

```ts
interface UserRow extends RowDataPacket {
  id: number
  name: string
  email: string
  created_at: Date
}
```

逐行翻译：

```text
interface UserRow
定义一种叫 UserRow 的对象形状

extends RowDataPacket
声明它是一种 mysql2 SELECT 结果行

id、name、email、created_at
声明这条 SQL 实际选择了哪些列，以及我们预期的列类型
```

`UserRow` 不是数据库实体，也不会自动读取数据库。它只是给编译器的描述。

Java 中可以把 `UserRow` 粗略理解为专门承接 SQL 查询结果的 PO/DO：

```java
class UserRow {
    Integer id;
    String name;
    String email;
    LocalDateTime createdAt;
}
```

#### 5D-5：为什么必须 `extends RowDataPacket`

mysql2 的 `execute<T>()` 不允许把任意类型放进尖括号。它要求 `T` 必须是 mysql2 认可的查询结果类型。

如果错误地写成：

```ts
interface UserRow {
  id: number
  name: string
  email: string
  created_at: Date
}

const [rows] = await pool.execute<UserRow[]>(sql)
```

严格类型检查会报告：

```text
TS2344: Type 'UserRow[]' does not satisfy the constraint 'QueryResult'
```

原因不是 `id` 或 `name` 写错，而是 mysql2 不知道 `UserRow` 属于它的查询结果行。加入继承：

```ts
interface UserRow extends RowDataPacket {
  id: number
  name: string
  email: string
  created_at: Date
}
```

现在 `UserRow[]` 同时表达两层信息：

```text
RowDataPacket[]：这是 mysql2 的 SELECT 行数组
UserRow[]：每一行还有 id、name、email、created_at
```

注意，`extends RowDataPacket` 只解决编译器约束，不会在运行时验证数据库真的返回了这些列。

#### 5D-6：SELECT 为什么使用 `UserRow[]`

完整查询代码：

```ts
async function findByEmail(
  pool: Pool,
  email: string
): Promise<User | null> {
  const [rows] = await pool.execute<UserRow[]>(
    `
      SELECT id, name, email, created_at
      FROM users
      WHERE email = ?
      LIMIT 1
    `,
    [email]
  )

  const row = rows[0]

  if (!row) {
    return null
  }

  return toUser(row)
}
```

为什么尖括号里是数组：

```ts
execute<UserRow[]>
```

因为 SELECT 无论查到零行、一行还是多行，mysql2 都把第一项返回为行数组：

```ts
[]                    // 没查到
[userRow]             // 查到一行
[userRow1, userRow2]  // 查到多行
```

即使 SQL 有 `LIMIT 1`，返回值仍然是数组。因此要读取：

```ts
const row = rows[0]
```

项目启用了 `noUncheckedIndexedAccess`，数组第一项可能不存在，所以 `row` 的类型是：

```ts
UserRow | undefined
```

必须判断后才能传给 `toUser`：

```ts
if (!row) {
  return null
}

return toUser(row)
```

#### 5D-7：INSERT 为什么使用 `ResultSetHeader`

INSERT 不返回用户行。它返回执行结果信息，例如：

```text
affectedRows：影响了多少行
insertId：新记录的自增ID
warningStatus：警告状态
```

所以写成：

```ts
const [result] = await pool.execute<ResultSetHeader>(
  'INSERT INTO users(name, email) VALUES (?, ?)',
  [input.name, input.email]
)
```

现在 TypeScript 知道：

```ts
result.insertId
result.affectedRows
```

都是合法属性。

如果不写 `<ResultSetHeader>`，`result` 会被理解成多种 MySQL 结果的联合类型。编译器不能确定它一定具有 `insertId`，于是会报告：

```text
Property 'insertId' does not exist on type 'QueryResult'
```

常用 SQL 与类型的对应关系：

| SQL | `execute` 泛型 | 第一项是什么 |
|---|---|---|
| SELECT | `UserRow[]` | 数据行数组 |
| INSERT | `ResultSetHeader` | 插入结果、`insertId` |
| UPDATE | `ResultSetHeader` | 更新结果、`affectedRows` |
| DELETE | `ResultSetHeader` | 删除结果、`affectedRows` |

#### 5D-8：为什么还要把 `UserRow` 转成 `User`

数据库模型：

```ts
interface UserRow extends RowDataPacket {
  id: number
  name: string
  email: string
  created_at: Date
}
```

业务模型：

```ts
interface User {
  id: number
  name: string
  email: string
  createdAt: Date
}
```

它们不应该混成同一个类型：

```text
UserRow.created_at  跟随数据库命名
User.createdAt      跟随 TypeScript 命名
```

用一个 Mapper 明确转换：

```ts
function toUser(row: UserRow): User {
  return {
    id: row.id,
    name: row.name,
    email: row.email,
    createdAt: row.created_at
  }
}
```

Mapper 不执行 SQL，也不处理业务规则，只负责形状转换。

#### 5D-9：把 SELECT、INSERT 和 Mapper 连起来

下面是一份可以独立通过严格类型检查的最小 MySQL Repository：

```ts
import mysql, {
  type Pool,
  type ResultSetHeader,
  type RowDataPacket
} from 'mysql2/promise'

interface CreateUserInput {
  name: string
  email: string
}

interface User {
  id: number
  name: string
  email: string
  createdAt: Date
}

interface UserRepository {
  findByEmail(email: string): Promise<User | null>
  create(input: CreateUserInput): Promise<User>
}

interface UserRow extends RowDataPacket {
  id: number
  name: string
  email: string
  created_at: Date
}

function toUser(row: UserRow): User {
  return {
    id: row.id,
    name: row.name,
    email: row.email,
    createdAt: row.created_at
  }
}

class MysqlUserRepository implements UserRepository {
  constructor(private readonly pool: Pool) {}

  async findByEmail(email: string): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    const row = rows[0]
    return row ? toUser(row) : null
  }

  private async findById(id: number): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    const row = rows[0]
    return row ? toUser(row) : null
  }

  async create(input: CreateUserInput): Promise<User> {
    const [result] = await this.pool.execute<ResultSetHeader>(
      'INSERT INTO users(name, email) VALUES (?, ?)',
      [input.name, input.email]
    )

    const user = await this.findById(result.insertId)

    if (!user) {
      throw new Error(`创建用户后无法读取记录：${result.insertId}`)
    }

    return user
  }
}

const pool: Pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

const userRepository: UserRepository = new MysqlUserRepository(pool)
```

从最后一行向上追踪：

```text
mysql.createPool(...) 创建 pool
        ↓
new MysqlUserRepository(pool) 保存为 this.pool
        ↓
findByEmail 使用 execute<UserRow[]>
        ↓
create 使用 execute<ResultSetHeader>
        ↓
toUser 把 UserRow 转成 User
```

#### 5D-10：为什么生产代码有时写联合类型

初学阶段先使用：

```ts
interface UserRow extends RowDataPacket {
  id: number
  created_at: Date
}
```

它对应当前教学项目的简单配置，最容易理解。

生产项目中可能看到：

```ts
interface UserRow extends RowDataPacket {
  id: number | string
  created_at: Date | string
}
```

这不是 TypeScript 故意制造不确定性，而是 mysql2 的运行时配置可能改变返回形式：

- BIGINT 超过 JavaScript 安全整数范围时，项目可能配置为返回字符串。
- 配置 `dateStrings` 后，日期可能返回字符串而不是 `Date`。
- 不同数据库字段类型和驱动配置会影响实际值。

只有项目真的启用了这些配置，才需要扩大类型。不要为了“看起来更生产级”提前写联合类型。

如果类型确实是联合类型，Mapper 就负责统一：

```ts
function toUser(row: UserRow): User {
  const id = Number(row.id)
  const createdAt =
    row.created_at instanceof Date
      ? row.created_at
      : new Date(row.created_at)

  if (!Number.isSafeInteger(id)) {
    throw new Error(`用户ID无效：${String(row.id)}`)
  }

  if (Number.isNaN(createdAt.getTime())) {
    throw new Error(`创建时间无效：${String(row.created_at)}`)
  }

  return {
    id,
    name: row.name,
    email: row.email,
    createdAt
  }
}
```

#### 5D-11：最常见的四个错误

错误一：SELECT 忘记写行数组类型。

```ts
// 错误
const [rows] = await pool.execute(sql)
const first = rows[0]

// 正确
const [rows] = await pool.execute<UserRow[]>(sql)
const first = rows[0]
```

错误二：`UserRow` 忘记继承 `RowDataPacket`。

```ts
// 错误
interface UserRow {
  id: number
}

// 正确
interface UserRow extends RowDataPacket {
  id: number
}
```

错误三：INSERT 忘记使用 `ResultSetHeader`。

```ts
// 错误：result 不一定具有 insertId
const [result] = await pool.execute(sql, params)

// 正确
const [result] = await pool.execute<ResultSetHeader>(sql, params)
```

错误四：把数据库行直接当成业务实体。

```ts
// 错误：UserRow 使用 created_at，User 使用 createdAt
return rows[0]

// 正确
const row = rows[0]
return row ? toUser(row) : null
```

### 6.6 完整 app.ts：作为 5D 最终参考

```ts
import 'dotenv/config'
import express, { type ErrorRequestHandler } from 'express'
import mysql, {
  type Pool,
  type ResultSetHeader,
  type RowDataPacket
} from 'mysql2/promise'

interface CreateUserBody {
  name?: unknown
  email?: unknown
}

type CreateUserDto = {
  name: string
  email: string
}

interface User {
  id: number
  name: string
  email: string
  createdAt: Date
}

interface UserOutput {
  id: number
  name: string
  email: string
  createdAt: string
}

interface UserRepository {
  findByEmail(email: string): Promise<User | null>
  create(input: CreateUserDto): Promise<User>
}

interface UserRow extends RowDataPacket {
  id: number | string
  name: string
  email: string
  created_at: Date | string
}

interface MysqlErrorLike {
  code?: unknown
}

class EmailAlreadyExistsError extends Error {
  readonly statusCode = 409
  readonly code = 'EMAIL_ALREADY_EXISTS'

  constructor() {
    super('该邮箱已被使用')
    this.name = 'EmailAlreadyExistsError'
  }
}

class DuplicateUserEmailError extends Error {
  constructor() {
    super('Duplicate user email')
    this.name = 'DuplicateUserEmailError'
  }
}

function isValidEmail(value: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
}

function isDuplicateEntry(error: unknown): boolean {
  return (
    typeof error === 'object' &&
    error !== null &&
    (error as MysqlErrorLike).code === 'ER_DUP_ENTRY'
  )
}

function toUser(row: UserRow): User {
  const id = Number(row.id)
  const createdAt =
    row.created_at instanceof Date
      ? row.created_at
      : new Date(row.created_at)

  if (!Number.isSafeInteger(id)) {
    throw new Error(`用户ID超出JavaScript安全整数范围：${String(row.id)}`)
  }

  if (Number.isNaN(createdAt.getTime())) {
    throw new Error(`数据库返回了无效时间：${String(row.created_at)}`)
  }

  return {
    id,
    name: row.name,
    email: row.email,
    createdAt
  }
}

class MysqlUserRepository implements UserRepository {
  constructor(private readonly pool: Pool) {}

  async findByEmail(email: string): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE email = ?
        LIMIT 1
      `,
      [email]
    )

    return rows[0] ? toUser(rows[0]) : null
  }

  private async findById(id: number): Promise<User | null> {
    const [rows] = await this.pool.execute<UserRow[]>(
      `
        SELECT id, name, email, created_at
        FROM users
        WHERE id = ?
        LIMIT 1
      `,
      [id]
    )

    return rows[0] ? toUser(rows[0]) : null
  }

  async create(input: CreateUserDto): Promise<User> {
    let insertResult: ResultSetHeader

    try {
      const [result] = await this.pool.execute<ResultSetHeader>(
        'INSERT INTO users(name, email) VALUES (?, ?)',
        [input.name, input.email]
      )
      insertResult = result
    } catch (error) {
      if (isDuplicateEntry(error)) {
        throw new DuplicateUserEmailError()
      }
      throw error
    }

    const createdUser = await this.findById(insertResult.insertId)

    if (!createdUser) {
      throw new Error(`创建用户后无法读取记录：${insertResult.insertId}`)
    }

    return createdUser
  }
}

class UserService {
  constructor(private readonly repository: UserRepository) {}

  async create(input: CreateUserDto): Promise<UserOutput> {
    const existingUser = await this.repository.findByEmail(input.email)

    if (existingUser) {
      throw new EmailAlreadyExistsError()
    }

    try {
      const user = await this.repository.create(input)

      return {
        id: user.id,
        name: user.name,
        email: user.email,
        createdAt: user.createdAt.toISOString()
      }
    } catch (error) {
      if (error instanceof DuplicateUserEmailError) {
        throw new EmailAlreadyExistsError()
      }
      throw error
    }
  }
}

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT ?? 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  waitForConnections: true,
  connectionLimit: 10,
  charset: 'utf8mb4',
  timezone: 'Z'
})

const userRepository: UserRepository = new MysqlUserRepository(pool)
const userService = new UserService(userRepository)
const app = express()

app.use(express.json())

app.post('/users', async (req, res, next) => {
  try {
    const body = req.body as CreateUserBody
    const rawName = body.name
    const rawEmail = body.email

    if (typeof rawName !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: 'name 必须是字符串'
      })
      return
    }

    if (typeof rawEmail !== 'string') {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: 'email 必须是字符串'
      })
      return
    }

    const input: CreateUserDto = {
      name: rawName.trim(),
      email: rawEmail.trim().toLowerCase()
    }

    if (input.name.length < 2 || input.name.length > 50) {
      res.status(400).json({
        success: false,
        code: 'INVALID_NAME',
        message: '用户名长度必须在 2 到 50 个字符之间'
      })
      return
    }

    if (!isValidEmail(input.email)) {
      res.status(400).json({
        success: false,
        code: 'INVALID_EMAIL',
        message: '邮箱格式不正确'
      })
      return
    }

    const user = await userService.create(input)

    res.status(201).json({
      success: true,
      code: 'USER_CREATED',
      message: '用户创建成功',
      data: user
    })
  } catch (error) {
    next(error)
  }
})

const errorHandler: ErrorRequestHandler = (
  error,
  _req,
  res,
  _next
) => {
  if (error instanceof EmailAlreadyExistsError) {
    res.status(error.statusCode).json({
      success: false,
      code: error.code,
      message: error.message
    })
    return
  }

  console.error('未处理的请求异常', error)

  res.status(500).json({
    success: false,
    code: 'INTERNAL_SERVER_ERROR',
    message: '服务器内部错误'
  })
}

app.use(errorHandler)

const port = Number(process.env.PORT ?? 3000)

app.listen(port, () => {
  console.log(`服务已启动：http://localhost:${port}`)
})
```

然后重新发送创建用户请求。这样一旦出错，你只需要检查刚移动的那一层。

## 8. 五个阶段到底增加了什么

| 阶段 | 新增概念 | 解决的问题 | 仍然故意不做 |
|---|---|---|---|
| 一 | 完整 HTTP 流程 | 看见业务全貌 | 不分层 |
| 二 | Service 函数 | HTTP 与业务分开 | Service 仍写 SQL |
| 三 | Repository 对象 | 业务与 SQL 分开 | 不使用 class 和接口 |
| 四 | class + 构造器注入 | 多方法共享依赖、方便替换 | 不加 TypeScript 类型 |
| 五 A | Service 输入和输出类型 | 看懂参数与 Promise 返回值 | Repository 暂时允许 any |
| 五 B | Repository 简单契约 | 编译阶段检查依赖的方法形状 | 不学 mysql2 泛型 |
| 五 C | HTTP 边界的 unknown | 把不可信请求转换为可信输入 | Service 不接触 unknown |
| 五 D | mysql2 Row 和 Result 类型 | 描述数据库驱动边界 | 不把泛型当成运行时校验 |

注意：后一个阶段不是在否定前一个阶段。

每个阶段都是在代码出现真实痛点后，增加恰好足够的结构。

---

## 9. 什么时候进入下一阶段

### 停在第一阶段

适合：

- 刚学 Express；
- 还不熟悉 req、res、next；
- 还不能独立写出一次 SELECT 和 INSERT；
- 练习代码只有一个接口。

目标不是目录漂亮，而是能不看教程写出：校验、查重、创建、返回。

### 进入第二阶段

当你能指出哪些代码是 HTTP 控制，哪些代码是创建用户业务时，抽 Service 函数。

### 进入第三阶段

当 Service 中的 SQL 妨碍阅读或测试时，抽 Repository 对象。

### 进入第四阶段

当多个 User 用例需要共享同一个 Repository 时，使用 class 和构造器注入。

### 进入第五阶段

当你已经理解对象之间的调用关系，再按照下面顺序进入，不要跳级：

```text
5A：只写 CreateUserInput、User、Promise<User>
5B：再把 repository: any 换成 UserRepository
5C：只在 HTTP 边界学习 unknown 和运行时校验
5D：最后才学习 mysql2 RowDataPacket 和 ResultSetHeader
```

任何一步开始影响你理解业务时，都可以退回上一步。JavaScript 第四阶段本身就是一个可以继续练习 Express 的有效版本。

### 进入生产版细分

当模块出现多个接口、多种 DTO、内部 Entity、多个数据源、复杂 Mapper 和多人协作时，再细拆文件。

## 10. 初学者最容易犯的学习错误

### 错误一：按文件名逐个硬啃

看到十个文件后，从 entity 开始读，再读 dto、schema、mapper，最后忘了接口究竟要做什么。

正确方式：先从一次 HTTP 请求开始，沿函数调用向下跟。

### 错误二：还没遇到问题就抽象

只有一个接口时，就创建通用 BaseRepository、AbstractService、DI Container。

正确方式：先写出重复或耦合，再抽取能解决它的最小结构。

### 错误三：把 class 当成分层

把一个函数包进 class，但 Service 仍然读取 `req.body`、返回 `res.json()`、执行 SQL。这不叫职责分离，只是换了语法。

### 错误四：把文件多当成生产级

生产级不等于文件多。生产级首先是：

- 数据正确；
- 输入可靠；
- SQL 安全；
- 错误可控；
- 代码可测试；
- 能稳定部署和排查。

### 错误五：一次重构十个文件

一次改 Route、Controller、Service、Repository、DTO、Mapper，出错后不知道是哪一步造成的。

正确方式：一次只移动一个职责，验证成功再继续。

### 错误六：相信 TypeScript 类型会校验运行时数据

下面的写法不会检查客户端请求：

```ts
const input = req.body as CreateUserInput
```

`as` 只让编译器暂时相信开发者，运行时不会检查 name 和 email。HTTP 请求、环境变量和数据库 Row 必须在边界进行真实校验或转换。

## 11. 最终应该记住的不是目录，而是演进原因

把五个阶段压缩成五句话：

```text
第一阶段：先看懂整个创建用户流程。
第二阶段：HTTP 代码太杂，所以抽 Service。
第三阶段：Service 被 SQL 淹没，所以抽 Repository。
第四阶段：多个用例共享依赖，所以使用 class 和构造器注入。
第五阶段：先给输入输出加类型，再给 Repository 加契约，再处理外部边界。
```

最终生产结构只是第五阶段继续发展的结果：

```text
Route → Controller → Service → Repository → MySQL
```

这个箭头从第一阶段就已经存在，只是最开始全部写在一个函数里。

因此，不要继续按照复杂项目的文件顺序硬啃。回到第一阶段，亲手写完一个 `app.post('/users')`；确认自己看得见业务，再进入下一阶段。
