# Agent 演示数据 Seed 设计

## 目标

为文章分析 Agent 提供一组可重复生成的演示数据，使它能够比较当前作者最近五篇 Vue 文章的收藏数、评论数量和评论内容，并据此生成一篇改进后的新文章。

Seed 必须避免依赖固定数据库主键，也不能清空或改动普通业务数据。

## 方案选择

采用数据库级 TypeScript 脚本，通过项目现有的 MySQL 连接配置执行参数化 SQL 和事务。

没有选择另外两种方案：

- 逐个调用 HTTP 接口：能够覆盖接口链路，但需要反复登录和维护多个 token，执行慢且失败点多。
- 纯 SQL 文件：执行简单，但不方便生成 bcrypt 密码、解析环境变量和提供清晰的幂等行为。

## 命令与入口

新增 npm 命令：

```text
npm run seed:agent-demo
```

脚本支持可选环境变量：

```text
SEED_AUTHOR_ID=16
```

- 设置 `SEED_AUTHOR_ID` 时，先验证该用户存在，再将五篇演示文章归属于该用户。
- 未设置时，创建或复用专用作者 `agent_demo_author`，并输出登录用户名和演示密码。
- 不直接指定任何新记录的数据库主键。

## 演示数据

脚本创建或复用：

- 一个专用演示作者（未指定 `SEED_AUTHOR_ID` 时）。
- 八个专用演示读者。
- Vue、JavaScript、TypeScript、Performance 标签。
- 五篇带固定 `agent-demo-` slug 前缀的 Vue 文章。
- 差异化收藏和评论，用于制造可解释的表现差异。

建议互动分布：

| 文章 | 收藏 | 评论 | 目的 |
| --- | ---: | ---: | --- |
| Vue 响应式基础 | 8 | 4 | 表现较好 |
| Vue 组件通信 | 5 | 3 | 表现中等 |
| Vue Router 入门 | 3 | 2 | 表现一般 |
| Vue 性能优化 | 1 | 3 | 互动较低且有问题反馈 |
| Vue Composition API | 0 | 1 | 最值得改进 |

评论内容覆盖正面反馈、中性提问、缺少示例、解释不清、内容过时和无法运行等场景。

## 幂等与数据安全

- 用户通过固定 `agent_demo_` 用户名和邮箱识别。
- 文章通过固定 `agent-demo-` slug 识别。
- 标签通过唯一名称创建或复用。
- 重复执行时更新演示文章内容和时间，不创建重复文章。
- 只删除并重建这五篇演示文章的 `article_tags`、`favorites` 和 `comments`。
- 不删除普通用户、普通文章或其他文章的互动数据。
- 所有写入在一个事务中完成，任一步失败都回滚。
- 生产环境默认拒绝执行；只有显式设置 `ALLOW_DEMO_SEED=true` 才允许在 `NODE_ENV=production` 下运行。

## 错误处理

- `SEED_AUTHOR_ID` 不是正整数时立即失败。
- 指定作者不存在时立即失败，不自动创建对应 ID。
- 用户名或邮箱被非配套演示账号占用时立即失败，避免覆盖未知用户。
- SQL 或密码散列失败时回滚事务并以非零退出码结束。
- 成功后输出作者 ID、登录信息、文章数量、收藏数量和评论数量。

## 验证

- 为纯数据定义和环境变量解析编写不依赖数据库的单元测试。
- 运行 TypeScript 类型检查。
- 在可用的本地数据库上执行 seed 两次，确认第二次不会增加文章、收藏或评论数量。
- 查询五篇固定 slug，核对作者、标签、收藏和评论分布。
