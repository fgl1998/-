# Agent 聊天页面实施计划

**目标：** 在 uniapp-v2 中完成可访问的 Agent 页面，复用当前登录身份调用 `POST /api/agent/chat`。

**设计：** 选择从“我的”页进入普通页面，方便返回退出并释放消息。相比新增常驻 tab 或弹窗，普通页面更符合当前临时聊天的范围。采用 Vue 2 Options API、uni-app 原生消息列表与输入框，配合现有 uView 按钮和蓝白配色。

**约束：** 每次请求只有 `{ message }`，读取 `{ answer }`；不传历史、不保存聊天到本地或服务端。消息在当前页内显示，卸载或切换账号清空。输入最多 2000 字符，空输入和重复发送不能触发接口。模型结果显示为可选择的纯文本，不注入 HTML。

**请求：** `config/env.js` 增加 `AGENT_BASE_URL = 'http://127.0.0.1:3002'`，依据当前 Agent 配置。`api/agent.js` 使用现有 `createHttpClient` 创建独立地址的客户端，发送时读取当前会话 Token。为 Agent 请求设置 120 秒等待；公共 HTTP 层只添加可选 timeout 与嵌套错误解析，保持原业务请求行为。401 继续复用清理登录和跳转逻辑。

**页面：** `pages/agent/chat.vue` 展示登录引导、能力说明、示例问题、用户/助手消息、处理中状态、错误和手动重试。失败问题保留，重试复用该问题；等待时锁定发送。使用请求代次及 Token 检查，拒绝卸载或账号变化后的旧响应。

**入口：** 在 `pages.json` 注册页面，在 `pages/my/my.vue` 菜单增加入口，并移除邮箱点击触发的硬编码 JWT 临时测试。

## 本地验证

在项目根目录执行 `node --test tests/*.test.js`；当前工作环境使用已安装的 Node 可执行文件运行，不安装或迁移依赖。

HBuilderX 中运行现有项目，登录后从“我的 → 智能助手”进入。确认文字可发送、长回答可滚动、失败可重试，返回再进入为空；真机联调需把两个后台地址改为电脑的局域网 IP。

## 验证记录（2026-09-03）

- 最终全部 79 个测试通过（原有 65 个、新增 14 个）；新增 HTTP 与 Agent 行为测试，并在修复前确认新用例失败。
- 独立复核发现“旧问题重试的回答追加到末尾”会打乱问答顺序，补充回归用例后改为插入对应问题后，并滚动到该回答。
- 聊天页和“我的”页通过本机 Vue 2 模板编译器检查。
- 浏览器以 375 × 812 视口，用实际页面脚本、API 和 HTTP 模块配合临时原生标签适配、模拟服务，验证示例填入、发送、失败重试、文字排版以及请求期间退出重入清空。模拟端确认请求仅含当前 message 且携带模拟登录 Token；该检查不等于真机联调。
- 整项目小程序构建未通过：本机旧版 HBuilderX 工具链无法解析现有 uView 文件中的可选链语法，并存在编译缓存目录权限错误。没有为此改动 uView 或安装依赖。
- 检查时本地 3000、3002 端口服务均未响应，没有调用真实模型。仍需服务启动后做真实回答与真机键盘检查。
