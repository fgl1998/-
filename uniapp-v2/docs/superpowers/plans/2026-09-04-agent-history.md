# Agent 历史记录接入

目标：在现有聊天页面进入后恢复当前用户的历史问答，继续使用同一个聊天接口。

接口：POST `/api/agent/history`，请求体 `{}`，使用 Agent 地址和当前 JWT；返回 `data.messages`，没有分页参数。后台已经按用户 ID 保存会话，前端继续仅向 chat 传当前 message。

设计（按用户要求更新）：采用聊天页自动恢复，不另建历史列表页。按 index 顺序逐条展示全部 human、ai、tool、system 及其他类型，不过滤中间阶段或空文本消息。区分消息类型，展示工具名称、关联调用 ID、完整工具调用参数和返回内容；结构化内容用格式化 JSON 展示。使用前端安全 ID，避免后端 ID 缺失或重复影响渲染。

状态：首屏读取期间禁用发送，避免历史覆盖新问题。读取失败展示重试入口，成功空列表展示原欢迎页。同一页面已加载后不因普通 onShow 重复覆盖消息；重新进入新页面重新读取后台。卸载、退出登录、切换账号使旧请求失效，不写本地聊天缓存。

新对话：chat 当前一次性返回 answer，回答完成后自动调用 history，用服务端的完整顺序替换临时问答，补齐查询文档等工具过程。刷新失败或返回空列表时保留已收到的回答，提供“重新加载过程”按钮，仅重试 history，不重复提交问题。尚未成功的本地问题保留重试入口。此实现并非流式展示，执行期间仍显示等待提示。

折叠交互：工具调用、工具结果、中间 AI、系统及其他过程消息默认收起，仅显示类型与工具名称。用户问题和最终回答默认展开。点击每条消息的标题栏可独立展开/收起，完整内容仍保留；折叠状态仅在当前消息列表中有效，重新读取历史后使用默认状态。此改动通过 21 项 Agent 回归测试、Vue 2 模板编译，以及默认状态、独立切换和完整内容保留检查。
